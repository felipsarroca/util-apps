# Auditoria funcional i proposta d'evolució

## Estat actual

- Backend: Google Apps Script.
- Dades: Google Sheets.
- Frontend: HTML, CSS i JavaScript integrat a Apps Script.
- Fluxos principals disponibles:
  - entrada per correu,
  - contrasenya comuna per professorat,
  - rols alumne, professor i admin,
  - creació de cicles,
  - creació de sessions,
  - selecció de comportaments,
  - autoavaluació, coavaluació i heteroavaluació,
  - dashboards bàsics.

## Correccions aplicades en aquesta revisió

- El formulari de login recorda l'últim correu i la contrasenya en aquest ordinador amb `localStorage`.
- El refresc després de crear sessió manté el token i no retorna al registre.
- La sessió caducada ja no cau al compte Google actiu: obliga a tornar a entrar.
- Les dades base es reparen una sola vegada per versió de catàleg, no en cada lectura.
- S'han revisat marcadors de codificació malmesa en fitxers principals.
- S'ha reforçat el footer i l'espai inferior perquè es vegi complet.
- S'han recol·locat els logos de Pentabilities i Escola Ramon Pont al login i a la capçalera.

## Funcionament esperat

### Alumne

1. Escriu el seu correu.
2. Entra sense contrasenya.
3. Introdueix el codi de sessió.
4. Fa autoavaluació i coavaluació.
5. No veu resultats ni gestió de sessions.

### Professor

1. Escriu el correu i la contrasenya comuna.
2. Veu només els seus cicles i sessions.
3. Crea cicles i sessions.
4. Heteroavalua sessions obertes.
5. Consulta dashboards dels seus cicles/sessions.

### Admin

1. Entra amb correu admin i contrasenya.
2. Pot veure tots els cicles i sessions.
3. Pot revisar i provar globalment el funcionament.

## Sobre migrar a frontend separat

Sí, una app HTML/CSS/JS o Vite separada seria millor per manteniment i disseny. No convé fer la migració total abans de validar el flux funcional amb alumnat real, perquè ara el backend depèn de `google.script.run` i la migració implica canviar el model de comunicació.

Proposta prudent:

1. Validar aquesta versió amb 4 ESO.
2. Separar el frontend en fitxers locals modulars.
3. Crear un client API únic.
4. Migrar pantalles una a una.
5. Mantenir Apps Script com a API provisional.
6. Valorar després Supabase o una base de dades pròpia si el volum creix.
